图例与标注解释

元素 / 颜色含义
蓝色方块 + 箭头主流程的八个工位及流转方向：选品 → 方向 → 大纲 → 圣经 → 分章写作 → 质检 → 包装 → 调度
深蓝方块（分章写作★）核心工位，整条流水线的"心脏"，内部有质量门槛闭环
赭色回环箭头两个"不合格重写"回路：① 字数不足带反馈重写；② 盲评不达标带原因重写，并沉淀到本书 lessons.json
绿色箭头达标路径：naturalness ≥4 的章节通过，进入质检环节
「模型分段写一章」GPT-5.5 每段写 300 词、段间冷却 3 秒，规避中转 60 秒超时；1200 词章节自动切成 4 段
「程序数字数」程序用正则数英文单词数，硬校验区间（默认 620-780，1200 词模式为 1080-1320），不达标生成具体反馈重写
「质量盲评 GPT」由另一个模型（GPT 优先、Gemini 兜底）盲评 naturalness（自然度 1-5），不达标（<4）触发重写
「沉淀 lessons.json」盲评失败的原因（verdict=ai 时）提取为"avoid 词条"存进本书教训库，下一章写作自动注入，实现书内自学习
输入（底部蓝框）方向文件 rec_N.txt、系统配置 config.json、AI 味词表、密钥 keys.local.json
中间产物（底部赭框）大纲 outline.md、设定圣经 world_bible.md、本书教训库 lessons.json
输出（底部绿框）章节 ch0001-0012.md、合订 full.md、中文摘要、EPUB 电子书、发布清单 publish_manifest

各阶段职责速查

阶段做什么关键实现
1 选品 radar抓榜单、抠书名/简介/标签、LLM 统计题材分布 + 找空位 + 推荐正则解析 HTML、关键词粗分类、LLM 严格 JSON 输出、24 小时去重
2 方向管理把推荐转成方向文件一行拼接 "题材: 创意"，写 rec_N.txt，标记已采纳
3 大纲生成 logline / 主角 / 三幕 / 逐章节拍每章强制 2-3 场景节拍 + 对话 + 细节揭示（字数达标根因）
4 设定圣经生成力量体系 / 世界规则 / 人物卡写章时逐章注入，标注 MUST stay consistent 防前后矛盾
5 分章写作 ★分段续写 + 字数硬校验 + 质量门槛300 词/段续写、程序数词、GPT 盲评重写、lessons 沉淀
6 质检拦截审稿评分（地道性/精彩度）+ 降级链GPT→GLM→Gemini 降级，低于阈值 exit 2 拦截不包装
7 包装生成 EPUB + 发布清单zipfile 手写 EPUB（mimetype 不压缩），清单含 AI 披露
8 调度看板限流 + 编排 + 前端控制日产量/token 预算检查，Web 看板一键开始/暂停/下载
