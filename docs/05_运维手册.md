## 2. 启动与停止

### 2.1 看板（日常监控）

```powershell
cd /d E:\novel pro
py -3 dashboard.py
# 浏览器打开 http://localhost:8900
```

看板功能：进度卡、推荐列表（采纳/跳过）、产物清单、开关、触发生产。

### 2.2 无人监管生产

```powershell
py -3 orchestrator.py --cycle      # 跑一次完整循环
py -3 orchestrator.py --dry-run    # 只预览命令
py -3 orchestrator.py --report     # 日结报告
```

建议用 Windows 计划任务定时触发 `--cycle`（见 5.2）。

### 2.3 手动分步（调试用）

```powershell
py -3 radar.py                              # 1 选品
py -3 direction_manager.py list             # 2 看推荐
py -3 direction_manager.py adopt --id N     # 3 采纳
py -3 engine.py --direction-file directions\rec_N.txt --story-id my_story --quality-gate
py -3 native_check.py --story-id my_story --sample 3
py -3 packager.py --story-id my_story
```

## 3. 日常运维

### 3.1 查看进度

- 看板：http://localhost:8900
- 实时状态：`logs/progress.json`
- 生产日志：`logs/*.out` / `logs/*.err`

### 3.2 查看产出

- 正文：`shorts/{story_id}/ch*.md`
- 包装：`out/{story_id}/`（EPUB + publish_manifest）
- 质检：`probe/native_check_result.json`

### 3.3 词条库管理（书内自学习）

每本书的优化词条库：`shorts/{story_id}/lessons.json`

```
{"lessons": [{"rule": "avoid over-orchestrated symbolic domestic detail", "source": "ch1 盲评 2 分", "ts": "..."}]}
```

- **作用**：该书后续章节写作时注入这些"避免项"，越写越贴本书
- **隔离**：只影响本书，全局规则包（ai_tells_en.json / profiles.py）只读不写，书与书零交叉
- **清理**：删掉该文件 = 该书停止自学习（从零开始）
- **备份**：lessons.json 随书目录一起备份即可

## 4. 监控配置

### 4.1 监控点

| 监控点 | 位置 | 正常表现 |
|---|---|---|
| 生产进度 | logs/progress.json | writing→verifying→packaging→done |
| 质量达标 | engine 输出 `quality=N` | quality ≥4 |
| 质检通过 | native_check exit code | 0=通过，2=质量不过被拦截 |
| 中转健康 | logs 里 504/400 | 偶发（自动重试），持续出现需关注 |
| 日产量 | orchestrator --report | ≤ max_stories_per_day |

### 4.2 告警建议（后续接入）

建议对以下事件加通知（微信/邮件）：
1. `write_failed` / `verify_failed`（流程中断）
2. 连续 3 次 504/400（中转异常）
3. 质检 exit 2（质量不过被拦截）
4. 日产量达上限

## 5. 故障处理手册

### 5.1 GPT 中转 504/400（最常见）

**现象**：日志出现 `HTTP 504: Gateway Time-out` 或 `400 upstream_error`。

**处理**：
1. 已加自动重试（3 次，间隔 3-6 秒），多数情况自愈
2. 若持续失败：`py -3 orchestrator.py --dry-run` 确认环境，等 5 分钟重跑
3. 若长时间不可用：切模型。config.json 的 writer 改回 `gemini-3.1-pro-preview`（需开 Clash）

### 5.2 Gemini 代理断

**现象**：`WinError 10061`（连接拒绝，Clash 7897 未开）。

**处理**：
1. 打开 Clash（代理 7897）
2. 或确认 config.json 用的是 GPT（直连无需代理）

### 5.3 检测链降级

检测自动按 `GPT → GLM → Gemini` 降级。日志里 `provider: gpt-5.5 (gpt)` 表示 GPT 生效。
若 GPT 挂了自动用 GLM，再不行 Gemini。

### 5.4 流程中断重跑

`--cycle` 中断后重跑会：
1. 重新雷达选品（可能推荐不同题材）
2. 已写好的书不会重复写（新 story_id）
3. 进度文件被覆盖

## 6. 阈值调整（重要参数）

| 参数 | 位置 | 当前值 | 说明 |
|---|---|---|---|
| 质量门槛 | orchestrator 里 `--quality-min` | 4 | naturalness 低于此分带反馈重写 |
| 质检地道性 | native_check.py SCORING_SPEC | native ≥4 | 低于此分 exit 2 拦截 |
| 质检精彩度 | native_check.py SCORING_SPEC | engagement ≥3 | 低于此分 exit 2 拦截 |
| 字数 | config.json writing | 620-780 | 每章词数硬范围 |
| 日产量上限 | orchestrator.json | 见文件 | max_stories_per_day |
| token 预算 | orchestrator.json | 见文件 | daily_token_budget |

**调整注意**：调高质检阈值 → 拦截更多 → 合格率下降但质量更稳；调低 → 生产更快但质量波动。
