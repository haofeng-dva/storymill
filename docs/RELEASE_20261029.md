## 新用户上手

以下命令按 Windows PowerShell 编写。`py -3` 需要 Python Launcher；也可以替换为你机器上的 `python` 命令。

### 第一章：装起来

#### 1. 环境要求

需要 Windows、Git 和 Python 3.10 或更新版本。应用和测试只使用标准库，**无需 `pip install` 任何第三方包**。当前回归测试是在 Python 3.13.14 上运行的。生产生成还需要你自己的可用模型服务、网关和 API key。

```powershell
py -3 --version
git --version
```

正常输出应包含 Python 3.10 或更新版本以及 Git 版本号。若 `py` 不存在，安装 Python 时启用 Python Launcher，或将后续命令中的 `py -3` 替换为 `python`。

#### 2. 拉取代码

```powershell
git clone https://github.com/haofeng-dva/storymill.git
cd storymill
```

目录中应看到 `engine.py`、`orchestrator.py`、`state_store.py`、`config.json`、`orchestrator.example.json`、`.env.example`、`tools/`、`test_*.py` 和 `README.md`。`state.db`、`shorts/`、`out/`、`logs/`、`directions/` 是本地产物，不随 Git clone 下载。

#### 3. 配置 API 和密钥

```powershell
Copy-Item .env.example .env
notepad .env
```

当前 `config.json` 默认正文/大纲模型走 OpenAI 兼容 relay，reviewer 和摘要模型走 Ark。因此默认完整生产至少要配置 `OPENAI_RELAY_BASE`、`OPENAI_RELAY_KEY` 和 `ARK_API_KEY`；只有切换到相应后端时才需要 Gemini 字段。雷达用到需登录的 Inkitt 来源时才需要 cookie。字段如下：

| 字段 | 用途 | 获取位置 |
| --- | --- | --- |
| `ARK_API_KEY` | `config.json` 的 `llm.api_key_env` 当前指定的 Ark 兼容服务凭据 | Ark/火山方舟服务商控制台 |
| `OPENAI_RELAY_BASE` | OpenAI 兼容中转服务的 API 基础地址，当前正文/大纲默认使用 | 中转服务商提供的 API 地址说明 |
| `OPENAI_RELAY_KEY` | 上述中转服务的访问凭据，当前正文/大纲默认使用 | 中转服务商控制台 |
| `GEMINI_API_KEY` | Gemini 后端凭据，仅切换到 Gemini 时需要 | Google/Gemini 服务商控制台 |
| `GEMINI_PROXY` | Gemini 请求代理地址；没有代理时可留空 | 自己配置的代理地址 |
| `INKITT_COOKIE` | 雷达遇到登录限制时可选的会话 cookie | 仅使用自己有权使用的浏览器会话 |

网关地址要填写服务商给出的 API 基地址，不是控制台网页地址。Ark 入口由 `config.json` 的 `llm.base_url` 设置；relay 入口通过 `OPENAI_RELAY_BASE` 设置。具体模型使用哪个后端由 `profiles.py` 和 `config.json` 的模型项共同决定。

`.env` 和 `keys.local.json` 已被 `.gitignore` 排除。密钥绝不要写入 Python 源码、`config.json`、README、日志或准备提交的文件。`.env.example` 只放空字段和说明，不放真实凭据。

#### 4. 创建并配置调度文件

```powershell
Copy-Item orchestrator.example.json orchestrator.json
notepad orchestrator.json
```

`config.json` 控制模型、API 基础地址、写作默认值和输出路径；`orchestrator.json` 控制调度、质量和预算。通常复制模板并保留默认设置即可。重点字段：

- `limits.max_stories_per_day`：每天最多完成的故事数。
- `limits.daily_token_budget`：每日 token 预算上限。启动新 run 前，系统按“当天已用 + 预计本单”判断；超过上限就拒绝启动。
- `limits.approx_tokens_per_story`：单次生产的预估 token，仅用于门禁预判，不会作为真实 token 写入账本。
- `quality.quality_min`：章节质量门槛。
- `switches.new_short_enabled`：是否允许自动生产新故事。
- `radar`：雷达来源、抓取数量和推荐配置。

预算按 UTC 自然日统计，跨日后自动使用新日期的 metrics。修改个人阈值应改本地 `orchestrator.json`，不要把个人设置写入模板后提交。

#### 5. 验证安装

```powershell
py -3 tools/check.py
```

正常结果示例：

```text
[OK] 闸门1 工作区: 已跟踪文件未提交差异 0 个；未跟踪 0 个
[OK] 闸门2 测试: 390 项，全部通过
[OK] 闸门3 提交: 最近 5 条提交信息可读
结果：三闸门全过，可以继续。
```

第一条检查工作区，第二条运行全量测试，第三条检查最近提交信息。新 clone 若尚无本地提交历史，提交闸门显示可能不同；不要为此伪造提交。

#### 6. 首次低成本试跑

用一章和 300 词目标确认自己的 key、网关和模型可以工作：

```powershell
py -3 engine.py --direction "A locked-room domestic suspense mystery in a small coastal town" --story-id first_probe --chapters 1 --words 300 --quality-gate --quality-min 4
```

这会实际调用模型并消耗 token。章节、`writing_status.json` 和运行状态写入 `shorts\first_probe\`；质检报告和包装产物写入 `out\first_probe\`；模型调用与 token 写入本地 `state.db`。预算预判不通过时，会在 `start_run` 前提示并以非零状态退出。

### 第二章：用起来

#### 1. 跑生产

一般新任务可直接调用引擎：

```powershell
py -3 engine.py --direction-file .\directions\my_direction.txt --story-id my_story --chapters 12 --quality-gate --quality-min 4
```

先创建 `directions\my_direction.txt` 并写入故事方向。`--chapters` 是章节数，`--words` 是每章目标词数，`--quality-min` 是质量阈值。所有参数以 `py -3 engine.py --help` 为准。

仓库脚本用途和限制：

- `run_try12.bat`：旧机器上的 12 章生产命令，固定 `E:\novel pro`、`directions\rec_1.txt` 和 `story_try_20260820`。stdout 写到 `logs\try12.out`，stderr 写到 `logs\try12.err`。新电脑需改掉绝对路径并提供自己的方向文件。
- `run_mm_werewolf_12ch_20261016.bat`：特定故事流程，复用或编译控制产物，先做 control dry-run，再运行 12 章生产。依赖对应的本地方向文件和已有产物，不是通用模板。
- `run_chapter_acceptance_three_probe.bat`：三章验收探针，固定小样本故事 ID，用于验证章节验收流程，不是完整生产脚本。

前台运行按 `Ctrl+C` 发出中断；引擎的 `finally` 会把 run 终结为 `aborted`。不要直接重启同一 run。检查 `shorts\<story-id>\writing_status.json`、章节文件和 `state.db` 后，才用原 `--run-id <ID> --resume` 恢复。Dashboard 的“暂停生产”只管理它启动的后台进程。

#### 2. 看进度

```powershell
py -3 dashboard.py
```

打开 `http://localhost:8900`。页面包括今日产量/限额、待采纳推荐、已生成故事及章节数、`out/` 产物、当前进度和质量阈值。`开始生产`触发 `orchestrator.py --cycle`；`暂停生产`停止 dashboard 启动的后台生产进程；质量阈值区域可以调整 `quality_min` 等值；报告按钮触发日结报告。按 dashboard 终端中的 `Ctrl+C` 关闭网页服务。服务只绑定 `127.0.0.1`，不要改成公网监听。

#### 3. 查用量与对账

```powershell
py -3 tools/usage.py
```

输出示例：

```text
今日 tokens: 12345
本月 tokens: 4510000
按 run:
run_abc    story_abc    12345    8 calls
```

第一行按 UTC 日期汇总，第二行按 UTC 月份汇总；其余行依次是 run ID、story ID、该 run token 总量和调用数。与服务商控制台对账时选择相同日期和模型范围。数字不一致可能是时区边界、控制台按请求计费、失败请求/内部重试的统计口径，或服务商用量延迟造成。该工具只读 `state.db`，不能手工改账。

#### 4. 预算耗尽

提示类似：

```text
今日 token 预算不足（已用 1900000 + 预计 500000 / 上限 2000000）
```

如确认需要提高当日上限，编辑本地 `orchestrator.json` 的 `limits.daily_token_budget` 后重新启动。不要改 `metrics` 或 `llm_calls` 绕过门禁。UTC 次日开始后会自动按新日期统计，不需要清空数据库。

#### 5. 质检与修复

章节验收失败时，系统会按配置执行有限次数的重试或有界修复，并把状态和证据存入 `state.db` 与故事目录。看到 `chapter acceptance unresolved`、连续 `model_error`、持续网络错误，或 `writing_status.json` 显示不可交付时，需要人工检查方向、凭据、失败章节和验收产物；确认原因后再决定是否使用 `--resume`。测试全绿只证明自动化检查通过，不等于正文经过人工审校。

#### 6. 常见问题

**`ModuleNotFoundError`**：项目本身不需要第三方包。确认命令在仓库根目录执行、使用 Python 3.10+，并检查 Python 安装是否完整；不要通过随意安装同名包掩盖环境错误。

**HTTP 401**：通常表示 key 缺失、错误或账号无权限。检查 `.env` 的字段名是否匹配 `config.json`/模型后端，并重启命令读取环境。

**HTTP 400**：通常表示请求格式、模型名或输入不被服务商接受。它不会自动重试；检查模型配置和错误正文，再调整请求。

**`tools/check.py` 提示未跟踪文件**：不会自动把文件加入 Git。不要执行 `git add .`；选择性暂存本任务文件，并排除 `_` 开头脚手架、密钥、数据库、日志和生成目录。

**历史 `.bat` 跑不起来**：脚本可能固定旧目录、故事 ID、方向文件或已有控制产物。查看脚本顶部路径和命令参数；新用户优先使用本文给出的 `engine.py` 命令。
