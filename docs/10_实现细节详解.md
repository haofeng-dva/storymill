### 1.1 抓榜：怎么拿到榜单

```python
def fetch(url, timeout=25):
    # 定义抓取函数：输入网址，返回网页文字
    # timeout=25 意思是：最多等 25 秒，超时就放弃
    req = urllib.request.Request(url, headers={"User-Agent": UA})
    # 构造一个"请求"（向服务器要东西的申请单）
    # User-Agent（浏览器标识）：伪装成正常浏览器，避免被网站当成机器人拒绝
    with urllib.request.urlopen(req, timeout=timeout) as resp:
        # 真正把请求发出去，resp 是服务器的回应
        return resp.read().decode("utf-8", "ignore")
        # read()：读回应的内容（网页源码）
        # decode("utf-8", "ignore")：把字节翻译成文字，ignore 表示遇到乱码字符跳过不报错
```

## 阶段 5：分章写作（write_with_retry + write_chapter）

### 5.1 完整写章 prompt（minimal 精简包，GPT-5.5/Gemini 3.1-pro 用）

```
Story direction: <方向>                          # 故事方向
Outline: <大纲>                                   # 故事大纲
World bible (settings that MUST stay consistent): <圣经>
# 世界圣经（设定必须保持一致）：<设定集>

Write Chapter 3 of 12, following the outline's beats.
# 写 12 章中的第 3 章，照着大纲的节拍写
Write the FULL chapter of 700 words, do NOT stop early.
# 写满 700 词，别提前停
Third person, past tense, start in-scene, end with a hook.
# 第三人称、过去时、从场景中间开始写、结尾留钩子（悬念）
Two hard rules:                                  # 两条硬规矩：
- No on-the-nose metaphors that map a character's profession directly onto their emotions
# 禁止"直白隐喻"：把职业硬套到情绪上（比如让会计写"平衡人生的账本"这种）
- No opening exposition dumps
# 禁止开头背景堆砌（一上来就倒背景资料，要用动作和细节慢慢带出来）

Output only the chapter text, no headers, no commentary.
# 只输出正文，不要标题、不要废话
```

### 5.2 （轻量模型 flash/deepseek 用）追加的内容

1. **anchor 样本**（锚点样本/风格范例）：同题材真人范文前 3000 字符，提示"imitate the voice, not the content"（模仿语气，别抄内容）
2. **禁用词表**（ai_tells_en.json 里的 AI 味词汇表）：
```
- Do NOT use these phrases: suddenly, as if, somehow, seemed to, her heart pounded...
# 禁止用这些短语："突然"、"仿佛"、"不知怎的"、"似乎"、"她心跳加速"...
- Avoid these tell-y verbs: chuckled, grinned, sighed, whispered...
# 避免这些"告诉式"动词（直接说情绪的词）：轻笑、咧嘴笑、叹气、低语...
- Avoid AI-template sensory clichés: fluorescent lights, stale coffee, damp uniforms...
# 避免 AI 爱用的感官陈词滥调：荧光灯、放凉的咖啡、潮湿的制服...
```
3. **情感缓冲规则**：
```
Emotional verisimilitude: when a character faces devastating news, betrayal, or shock,
write the emotional response FIRST (physical reaction, hesitation, denial, internal
struggle) before any rational or investigative action.
# 情感真实性：人物遭遇噩耗/背叛/震惊时，先写情绪反应（身体反应、迟疑、否认、内心挣扎），
# 再写理智行动。人物不能瞬间冷静地开始分析
```
4. **本书 lessons**（书内自学习沉淀的词条，前面章节踩过的坑）

### 5.3 字数硬校验循环（write_with_retry：写→数→不合格重写）

```python
for attempt in range(1 + max_rewrite):
    # 循环最多 max_rewrite+1 次（默认最多 4 次机会）
    r = self.write_chapter(..., fb, extra_rules)
    # 调模型写一章，fb 是字数反馈，extra_rules 是额外规则
    text = r["content"]
    wc = count_words(text)
    # count_words（数字数函数）：用正则 [A-Za-z']+ 数出英文单词个数
    if lo <= wc <= hi: return text
    # 字数在 620-780 区间内就通过，返回正文

```

**字数反馈生成**（具体说差多少、怎么补，不是说"写长点"）：
```

          Expand: add concrete sensory detail, one more exchange of dialogue,
          or a beat of interior thought. Do not pad with filler or repeat yourself."
# "你写了 563 词，差 137 词。补充：具体的感官细节、再加一段对话、或一段内心活动。
#  不要注水、不要重复。"

wc > hi: "You wrote 823 words, about 123 over. Trim redundancy, tighten sentences,
          cut filler words and repeated beats."
# "你写了 823 词，超了 123 词。删冗余、收紧句子、砍掉废话和重复的节拍。"
```

### 5.4 GPT 分段续写（_write_chapter_segmented：拆小段写，绕过超时）

```python
seg_words = 300
# 每段目标 300 词
n_segs = max(1, ceil(target_words / 300))
# 算出需要写几段（700 词需要 3 段）
for i in range(n_segs):
    # 循环写每一段
    if i == 0:
        user = base + f"Write the opening ~{seg_words} words of this chapter."
        # 第一段：让模型写开头 300 词
    else:
        user = base + f"Continue the chapter seamlessly, writing the next ~{seg_words} words."
                   + f"\n\nWritten so far:\n{full[-1500:]}"
        # 后面的段：把"已经写的最后 1500 字符"喂回去，让它无缝接下去写
    r = self.llm.chat("writer", [...], max_tokens=2000)
    # 调模型写这一段
    full += seg
    # 把新写的接在全文后面
    if count_words(full) >= target_words: break
    # 字数够了就停
```

**做到的关键**：每段喂"已写的最后 1500 字符"保证衔接；每段是独立小任务，都能在 60 秒（中转超时线）内完成。

### 5.5 AI 味密度校验（ai_tell_check：写完后检查 AI 味重不重）

```python
k = words / 1000.0
# 把总词数换算成"千词"单位（方便算密度）
for term in phrases + verbs + expressions:
    # 遍历所有禁用的词（短语/动词/表情动作）
    n = count(text, term)
    # 数这个词在文章里出现几次
    if n > 0 and n / k > 1.5:
        # 每千词出现超过 1.5 次就算超标
        issues.append(f"{term} x{n}")
        # 记进问题清单
em_rate = text.count("—") / k
# 数破折号"——"的数量，换算成每千词的密度
if em_rate > 8: issues.append(f"em-dash {em_rate:.1f}/k")
# 每千词超过 8 个破折号也算问题（AI 爱用破折号）
```

```python
# sys.exit（退出程序）：有不合格就退出码 2（拦截信号），全过就退出码 0（正常）
# 调度器看到退出码 2 就跳过包装这一步
```

## 阶段 8：包装（packager.py）

### 8.1 EPUB（电子书格式）怎么手写（zipfile 压缩包处理）

```python
with zipfile.ZipFile(out_path, "w") as z:
    # 打开一个压缩包文件准备写入（EPUB 本质上就是个特殊结构的压缩包）
    z.writestr("mimetype", "application/epub+zip", compress_type=zipfile.ZIP_STORED)
    # 第一个写 mimetype（文件类型声明）文件，必须"不压缩"（ZIP_STORED），这是 EPUB 规范
    z.writestr("META-INF/container.xml", ...)
    # 写容器声明文件：告诉阅读器主文件（content.opf）在哪
    z.writestr("OEBPS/content.opf", content_opf)
    # 写主配置文件：书的元数据（标题/作者/语言）+ 文件清单 + 阅读顺序
    z.writestr("OEBPS/nav.xhtml", nav)
    # 写目录文件（导航页）
    for i, text in enumerate(chapters, 1):
        z.writestr(f"OEBPS/ch{i}.xhtml", chapter_xhtml(i, text))
        # 每一章单独转成网页文件写进去
```

**做到的关键**：
1. `mimetype` 必须**不压缩**且**第一个写入**（阅读器靠这个认格式）
2. `content.opf`（主配置文件）里要有标题/作者/语言 + manifest（清单）+ spine（阅读顺序）
3. 每章 Markdown 先经 `md_to_html`（Markdown 转网页函数）转成 XHTML（网页标记语言）

### 8.2 发布清单

packager 用 LLM 生成 title（标题）/synopsis（简介）/tags（标签），校验必填字段：
`title / synopsis / chapters / aiDisclosure`（AI 披露声明，合规要求，必须写清楚这是 AI 写的）。
输出 `publish_manifest.json`（结构化，给机器读）+ `.md`（人读版）。

## 阶段 9：调度（orchestrator.py）

### 9.1 限流检查（check_limits：三关都过才放行）

```python
if not cfg["switches"]["new_short_enabled"]: return False, "switch off"
# 第一关：总开关（new_short_enabled 是否开启），没开就不跑
if m["stories"] >= limits["max_stories_per_day"]: return False, "daily cap"
# 第二关：今天的产量达到上限了吗？到了就不跑
if tokens + approx_tokens_per_story > daily_token_budget: return False, "token budget"
# 第三关：token（令牌，计费单位）预算够吗？超了就不跑
```

### 9.2 逐步执行（run_step：调用别的脚本）

```python
r = subprocess.run(cmd, shell=True, cwd=HERE, capture_output=True, timeout=timeout)
# subprocess.run（启动子进程）：在命令行执行一条命令（比如跑 radar.py）
# capture_output=True：把命令的输出抓回来
# timeout=timeout：超时限制（写章这步给 7200 秒，因为很慢）
ok = r.returncode == 0
# 命令退出码是 0 就代表成功（0 是正常的成功信号）
```

写作步骤超时 7200 秒（GPT 分段 + 质量重写很慢），质检 3600 秒。

### 9.3 质量门槛接入（把阈值传给写作脚本）

```python
quality_min = cfg["quality"]["quality_min"]      # 从配置文件读质量门槛（默认 4）
cmd = f'py -3 engine.py --direction-file "..." --story-id {story_id} --quality-gate --quality-min {quality_min}'
# 拼命令：跑写作引擎时带上 --quality-gate（开质量门槛）和 --quality-min 4（最低自然度）
```

### 9.4 质检拦截（质量不过就不包装）

```python
ok, tail = run_step("verify", "py -3 native_check.py --story-id ... --sample 3", timeout=3600)
# 跑质检脚本（抽前 3 章审）
if not ok:
    return {"status": "verify_failed"}
    # 质检没过（退出码非 0）→ 返回"质检失败"状态 → 调度器跳过包装
```
