# storymill 全流程逻辑与算法详解

> 版本：v1.0 | 更新：2026-08-14
> 覆盖：选品 → 方向 → 大纲 → 圣经 → 分章写 → 质量门槛 → 质检 → 包装 → 调度
> 配套：docs/02_PRD、03_架构设计、05_运维手册

---

## 1. 系统总览

### 1.1 一句话原理

**模型负责想（大纲、圣经、写章），程序负责查（数字数、判达标、管教训）。**
模型擅长但不可靠，程序可靠但不聪明，系统让可靠的管住不可靠的。

### 1.2 模块与职责

| 模块 | 阶段 | 一句话职责 |
|---|---|---|
| radar.py | 选品 | 抓榜统计赛道空位，LLM 产出题材推荐 |
| direction_manager.py | 方向 | 采纳推荐，生成方向文件 |
| engine.py | 大纲/圣经/写作 | 规划 + 逐章写作 + 质量门槛 |
| profiles.py | 模型路由 | 按模型能力选 prompt 策略 |
| native_check.py | 质检 | 审稿评分 + 盲评 + 降级链 |
| packager.py | 包装 | 生成 EPUB + 发布清单 |
| orchestrator.py | 调度 | 全流程编排 + 限流 + 拦截 |
| dashboard.py | 前端 | 一键开始/暂停、阈值、下载 |

## 2. 全流程逻辑（逐阶段）

### 阶段 1：选品（radar.py）

```
输入: 无（读配置）
处理:
  1. 抓 RoyalRoad 三榜（best-rated / complete / trending）
  2. 统计题材分布（各题材占比硬数字）
  3. LLM 基于统计数字推荐 5+ 条（genre/concept/confidence/reasoning/benchmarkTitles）
  4. 相似度去重（避免重复推荐相同题材）
  5. 写入 state.db recommendations 表
输出: state.db 待采纳推荐 + radar_en/scan-*.json 快照
```

### 阶段 2：方向管理（direction_manager.py）

```
输入: state.db 待采纳推荐（top1）
处理: adopt 采纳 → 把 concept 写成方向文本
输出: directions/rec_N.txt（喂给写作引擎的方向描述）
```

### 阶段 3：大纲生成（engine.py write_outline）

```
输入: 方向文本 + 配置（默认 12 章、700 词/章）
处理: LLM 生成结构化大纲（英文 prompt）
输出: shorts/{story_id}/outline.md
```

**outline.md 结构**（LLM 被要求输出）：
```
1. Logline（一句话故事）
2. Protagonist（name, flaw, want）
3. 3-act structure summary
4. 逐章 beats：每章 2-3 scene beats + 至少一段对话 + 一个具体细节揭示
```

**算法关键**：每章 beats 必须充足（这是字数达标的根因——"没料可写"才会注水）。

### 阶段 4：设定圣经（engine.py write_world_bible）

```
输入: 方向 + 大纲
处理: LLM 生成紧凑的内部一致设定
输出: shorts/{story_id}/world_bible.md（力量体系/世界规则/人物卡）
作用: 写章时逐章对照，防止写到第 8 章忘了第 1 章的规则
```

### 阶段 5：分章写作（engine.py write_with_retry）

```
输入: 方向 + 大纲 + 圣经 + 章号 n + 目标字数 700 + 历史反馈
处理: write_chapter 按模型 profile 选 prompt → 生成 → 程序数字数 → 不符带反馈重写
输出: shorts/{story_id}/ch{n:04d}.md
```

**核心循环（伪代码）**：
```
for attempt in range(1 + max_rewrite):      # 最多 4 次
    text = LLM.write(prompt)                 # 写一章
    wc = count_words(text)                   # 程序数词
    if lo <= wc <= hi:                       # 620-780 达标
        return text
    feedback = build_feedback(text, wc)      # 生成具体反馈
    prompt += feedback                       # 带反馈重写
```

**反馈算法**（build_feedback / _word_feedback）：
- 太短（<620）：报"差 N 词"，建议"补一段对话 / 补感官细节 / 补一段内心活动"，禁止注水
- 太长（>780）：报"超 N 词"，建议"删冗余 / 收紧句式 / 砍重复节拍"

### 阶段 6：质量门槛（engine.py + QualityJudge）

```
输入: 写好的章节 + 本书 lessons.json
处理: QualityJudge 盲评 naturalness（1-5）→ <4 带原因重写 + 沉淀教训
输出: 达标章节 + shorts/{story_id}/lessons.json
```

**循环（伪代码）**：
```
for qa in range(1 + 4):                      # 最多重试 4 次
    lessons = load_lessons(story_id)         # 读本书教训
    text = write_with_retry(... + lessons + feedback)
    wc = count_words(text)
    if wc < word_min:                        # 字数不足也重写
        feedback = "word count too short..."
        continue
    score, reason = QualityJudge.blind(text) # 另一模型盲评
    if score >= quality_min (4):             # 达标
        return text
    if verdict == ai:                        # 只沉淀 AI 味教训
        add_lesson(story_id, reason)         # 写入本书 lessons.json
    feedback = "Quality issue: " + reason    # 带原因重写
```

**lessons.json 格式**：
```json
{"lessons": [{"rule": "avoid over-orchestrated symbolic domestic detail", "source": "ch1 盲评 2 分", "ts": "2026-08-14T11:49:12"}]}
```

**隔离规则**：只写本书目录，全局规则包（ai_tells_en.json / profiles.py）只读，书与书零交叉。

### 阶段 7：质检（native_check.py）

```
输入: shorts/{story_id}/ 章节（抽样前 3 章）
处理: 降级链审稿 → 评分 → 低于阈值 exit 2
输出: probe/native_check_result.json + exit code（0 通过 / 2 拦截）
```

**审稿降级链**：GPT-5.5 → GLM-5-2 → Gemini 3.1-pro（谁通谁顶上）。

**评分维度（SCORING_SPEC）**：
| 维度 | 阈值 | 含义 |
|---|---|---|
| native 地道性 | ≥4 | 1=明显机翻，5=母语级可发布 |
| engagement 精彩度 | ≥3 | 1=平淡，5=抓人 |

**拦截**：任一维度低于阈值 → exit 2 → orchestrator 不包装。

### 阶段 8：包装（packager.py）

```
输入: shorts/{story_id}/ 全部章节 + 元数据
处理: 生成发布清单 + 手写 EPUB（zipfile）
输出: out/{story_id}/
      ├── {slug}.epub（标准 EPUB，16 文件规范）
      ├── publish_manifest.json（结构化元数据）
      └── publish_manifest.md（人读版）
```

### 阶段 9：调度（orchestrator.py）

```
输入: orchestrator.json（限流/阈值/开关）+ state.db
处理:
  1. check_limits（日产量上限 + token 预算 + 总开关）
  2. 依次跑: radar → adopt → engine(--quality-gate) → native_check → packager
  3. 质检 exit 2 拦截，不包装
输出: state.db 产量记录 + 进度日志
```

**限流参数**：max_stories_per_day、daily_token_budget、approx_tokens_per_story。

### 3.2 中间产物

## 4. 核心算法详解

### 4.1 模型路由算法（profiles.py）

**原理**：实测发现"给强模型太多约束反而有害"（full 包 3 分 vs minimal 包 5 分）。按模型能力自动选 prompt 策略。

```
get_writer_profile(model):
    for key, prof in WRITER_PROFILES.items():
        if model.startswith(key): return prof
    return 默认 full 包 + ark 后端
```

| 模型类型 | prompt 包 | max_tokens |
|---|---|---|
| thinking 强模型（gemini-3.1-pro / gpt-5.5）| minimal 精简 | 6000 / 4000 |
| 轻量（flash-lite / 3-flash-preview / deepseek）| full 完整 | 4096 / 2000 |

### 4.2 写章 prompt 构造（minimal vs full）

**minimal 包**（强模型）：方向 + 大纲 + 圣经 + 字数 + 2 条硬规则 + 反馈。
2 条硬规则：
1. 禁 on-the-nose 隐喻（职业比喻硬套情绪）
2. 禁开头背景堆砌

**full 包**（轻量模型）：minimal 基础上追加：
1. anchor 样本（同题材真人范文 few-shot）
2. 禁用词表（ai_tells_en.json）
3. 情感缓冲规则（先写身体反应再写行动）
4. 本书 lessons（书内教训）

### 4.3 GPT 分段续写（_write_chapter_segmented）

**原理**：GPT 中转 60 秒超时，一次写 700 词会 504。拆成 300 词/段续写。

```
seg_words = 300
n_segs = ceil(target_words / 300)
for i in range(n_segs):
    if i == 0:
        prompt = base + "Write the opening ~300 words"
    else:
        prompt = base + "Continue, writing the next ~300 words" + "Written so far: " + full[-1500:]
    seg = LLM(prompt)
    full += seg
    if count_words(full) >= target_words: break
return full
```

**关键**：每段把已写的最后 1500 字符喂回去，保证衔接；每段子任务在超时线内。

### 4.4 AI 味抑制（_forbidden_block + ai_tell_check）

**写前**：把词表注入 prompt 禁止（禁用词：suddenly / as if / her heart pounded / narrowed his eyes 等 + cliche_sensory：fluorescent lights / stale coffee 等）。

**写后**：程序统计密度：
```
for term in tells:
    n = count(text, term)
    if n > 0 and n / (words/1000) > 1.5:   # 每千词密度超 1.5
        issues.append(term)
em_rate = text.count("—") / (words/1000)    # 破折号密度
if em_rate > 8: issues.append("em-dash")
```

### 4.5 质量盲评（QualityJudge）

**原理**：写和评用不同角色，避免自我偏好放大（LitBench：同一模型评审偏爱自己风格）。

```
QualityJudge.blind(text):
    GPT 盲评 → 成功返回 (score, content, provider="gpt")
    GPT 失败 → Gemini 兜底
    解析: verdict (ai|human), naturalness (1-5), reason
```

**reason 规则**（prompt 强制）：
- verdict=ai：`reason: avoid <具体AI味>`
- verdict=human：`reason: natural`

### 4.6 书内自学习（load_lessons / add_lesson）

```
load_lessons(story_id): 读 shorts/{story_id}/lessons.json → 规则列表（最多取最近 20 条）
add_lesson(story_id, rule): 去重追加 {rule, source, ts} 到本书 lessons.json
```

**注入时机**：每章每次写之前读最新 lessons，拼接进 prompt：
```
Previous quality issues to avoid in THIS book (hard rules for this book only):
- avoid over-orchestrated symbolic domestic detail
- ...
```

### 4.7 质检降级链（review_with_fallback）

```
reviewers = [("gpt", GPT), ("gemini", Gemini), ("glm", GLM)]
for name, reviewer in reviewers:
    r = reviewer.review(text)
    if 无 error 且非空: return (content, provider)
return (None, "全部失败")
```

### 4.8 字数反馈算法（_word_feedback）

```
wc < lo: "你写了 wc 词，差 target-wc 词。补充：具体感官细节 / 一段对话 / 一段内心活动。禁止注水或重复。"
wc > hi: "你写了 wc 词，超 wc-target 词。删冗余、收紧句式、砍重复节拍。"
```

```
┌──────────────────────────────────────────────────────────┐
│ 输入: 方向文本 / 配置 / 密钥                               │

```
