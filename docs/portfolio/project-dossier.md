# Storymill：AI 英文短篇小说生产与质量控制引擎

归档日期：2026-10-27

## 项目定位

Storymill 是一套面向英文短篇和短篇连载的 Python 生产系统。它把选题、方向采纳、大纲、世界观、分章写作、章节验收、质量检查、问题修复和 EPUB 包装串成一条可恢复、可观测的流程，并保留人工介入入口。

项目在本次归档时停止继续扩展，公开仓库用于展示系统设计、工程实现、测试证据和真实限制。它不是一个“自动生成即可直接发布”的承诺。

## 解决的问题

- 长请求可能被上游网关在约 60 秒处截断，导致长篇生成半途停止。
- “文件写出来”与“章节满足要求”容易被混为一谈。
- 模型生成的事实、人物、伏笔和场景状态需要在章节之间传递并可追踪。
- 质量问题需要区分网络/模型故障、确定性文本问题和需要人工判断的编辑问题。
- 生产失败后需要知道已完成什么、失败在哪里、是否可以从断点恢复。

## 系统结构

```text
radar.py              选题雷达与推荐入库
direction_manager.py  推荐采纳与方向文件
engine.py             大纲、world bible、分章写作与章节验收
control_*.py          章节合同、场景账本、事实槽位和状态控制
story_bible*.py       故事事实库与写后核对
quality_checks.py     本地字数、重复、格式和风格检查
quality_gate.py       证据驱动的质量门禁与修复路由
repair_*.py           锚定问题队列、修复计划、复查和关闭记录
native_check.py       母语级审稿与结构化问题账本
final_editor*.py      终审候选、编辑计划和候选验证
packager.py           发布清单与 EPUB 包装
orchestrator.py       流程编排、限流、恢复和日结报告
dashboard.py          Web 看板与人工介入
state_store.py        SQLite 状态与调用审计
tests                 合同、状态、写作、验收、质量和包装回归
```

## 关键工程实现

### 可恢复的生产状态

每次运行使用 `run_id` 和章节任务状态记录，保存写作阶段、验收阶段、重试、错误类别、耗时和模型调用信息。恢复运行可以复用已有大纲和 world bible，只补跑 `pending` 或 `failed` 任务。

### 流式模型调用

写作、大纲和状态同步支持流式接收；请求按“空闲多久没有新数据”判断超时，并保存 HTTP 状态、provider failure、耗时和 token 信息。一次历史长请求从约 60 秒网关截断改为流式完成约 125 秒，验证了网络层修复方向。

### 章节级控制与质量门禁

大纲会进一步编译为章节合同、场景清单、人物声音卡、事实槽位和篇幅规则。章节写完后先做确定性检查，再做结构化验收；未满足合同的正文保留候选和失败证据，不直接伪装成完成。

### 锚定修复与问题账本

修复项携带章节、场景、当前正文哈希、原文锚点、上下文、修改范围和复查状态。修复前后保留 diff 和状态变化；已解决项保留历史，新问题可以重新打开。主观编辑观察与确定性阻断分开统计。

### 包装与人工交接

系统可以生成 `full.md`、EPUB、发布清单、中文摘要和推广材料；看板和运维手册保留人工采纳、跳过、复核和重新运行入口。

## 诚实的项目状态

已经验证：完整 12 章生产、章节级验收接线、失败分类、断点状态、流式接收、确定性文本检查、问题账本和 EPUB 包装路径。

尚未证明：所有新增事实/控制层在真实三章或完整 12 章生产中稳定闭环；一次超过 90 秒的真实流式验收样本；全书编辑质量达到发布标准；模型噪声下的单次重跑能证明质量改进。

因此简历和 GitHub 介绍应使用“完成了生产与质量控制基础设施”“有可复核的 12 章样稿和回归证据”，不要使用“自动稳定产出可直接发布小说”。
