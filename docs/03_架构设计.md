## 1. 总体架构

四层流水线 + 统一状态存储 + 模型封装层 + 书内自学习。

```
                    ┌─────────────────────────────┐
                    │  模型层（profiles.py 路由）    │
                    │  写作：GPT-5.5 分段 / Gemini   │
                    │        3.1-pro / deepseek    │
                    │  检测：GPT → GLM → Gemini     │
                    └──────────────┬──────────────┘
                                   │
  ┌────────────┐  ┌────────────┐  ┌────────────┐  ┌────────────┐
  │ L1 选品层   │→│ L2 生产层   │→│ L3 质检层   │→│ L4 包装层   │
  │ radar.py   │ │ engine.py  │ │ native_check│ │ packager.py│
  │ 榜单抓取    │ │ 大纲→bible │ │ 审稿评分    │ │ 清单+EPUB  │
  │ 空位量化    │ │ 分章+字数  │ │ 质量盲评    │ │            │
  │ LLM 推荐    │ │ 质量门槛   │ │ 拦截 exit 2│ │            │
  └────────────┘  └────────────┘  └────────────┘  └────────────┘
        │               │  │              │
        │               │  └── lessons.json（书内自学习，仅本书）
        │               │
        │          ┌────┴──────────┐
        │          │ L5 调度层       │
        └─────────▶│ orchestrator   │
                   │ dashboard 看板 │
                   │ progress 监测  │
                   └────────────────┘

统一状态存储：state.db（SQLite，编排状态）
文件仓库：radar_en/ directions/ shorts/ out/ probe/
```

## 2. 关键设计

### 2.1 模型封装（profiles.py）

每个模型绑定一个"包"（backend + prompt 策略 + 输出预算），按模型名自动路由：

| 模型类型 | prompt 包 | 说明 |
|---|---|---|
| thinking 强模型（gemini-3.1-pro / gpt-5.5）| minimal 精简包 | 约束反而拖累强模型，只给方向+大纲+字数 |
| 轻量模型（flash-lite / 3-flash-preview / deepseek）| full 完整包 | 约束（AI味词表/情感缓冲）辅助完成 |

**实测依据**：gemini-3.1-pro 用 full 包 naturalness 3，minimal 包 5。

### 2.2 GPT 分段续写

GPT 中转 60 秒超时（写 700 词会 504），`_write_chapter_segmented` 每段 300 词续写拼接。实测 818 词、naturalness 5、不退化。

### 2.3 质量门槛（engine.py）

每章写后 QualityJudge（GPT 优先 + Gemini 兜底）盲评 naturalness，<4 带反馈重写，字数 <620 也重写。最多重写 4 次。

### 2.4 质检拦截（native_check.py）

SCORING_SPEC：native ≥4 / engagement ≥3。低于门槛 exit 2，orchestrator 拦截不包装。

### 2.5 书内自学习（lessons.json）

- 盲评失败（verdict=ai）→ 提取 "avoid ..." 词条 → 沉淀 `shorts/{story_id}/lessons.json`
- 后续章节写作注入本书词条
- **隔离**：全局规则包只读，书与书零交叉

### 2.6 检测降级链

reviewers = [GPT, GLM, Gemini]，GPT 优先，挂了自动降级。

### 2.7 并行调度（设计定稿，未落地）

分章写作计划从串行改为块状并行（块内串行保依赖链 + 块间并行提速），配套交接卡与接缝修复机制。详细设计、已否决方案与里程碑见 docs/04_并行调度设计.md。

## 3. 数据流

```
radar 选品 → direction_manager 采纳 → engine 写作(质量门槛)
  → native_check 质检(拦截) → packager 包装 → 交付
                    ↑
         本书 lessons.json 词条回灌（仅本书）
```

## 4. 模块接口

| 模块 | 关键接口 |
|---|---|
| engine.py | `--direction-file --story-id --quality-gate --quality-min --extra-rules` |
| native_check.py | `--story-id --sample N --file`；exit 0/2 |
| orchestrator.py | `--cycle --report --dry-run` |
| dashboard.py | http://localhost:8900 |
| profiles.py | `get_writer_profile(model)` / `get_reviewer_profile(model)` |

## 5. 存储设计

| 存储 | 内容 |
|---|---|
| state.db | 推荐、方向、产量、token 指标 |
| shorts/{story_id}/ | 章节、outline、world_bible、lessons.json |
| out/{story_id}/ | 包装产物（EPUB、manifest）|
| probe/ | 质检结果 json |
| logs/ | 运行日志 + progress.json |

## 6. 演进说明（相对 v2.0）

| v2.0 设计 | v3.0 实际 |
|---|---|
| 写作引擎接母语级模型（Claude/GPT-4o/Gemini）| 定为 GPT-5.5 分段续写为主 |
| "DeepSeek 不参与英文正文写作" | deepseek-flash 保留为兜底/选品/摘要 |
| 质量门槛：L3 不达标不过 L4 | 细化为盲评 naturalness ≥4 + 审稿 native ≥4 双关 |
| 无书内学习 | 新增 lessons.json 书内自学习闭环 |
| 无模型封装层 | 新增 profiles.py 自动路由 |
